What each number stands for

Page 2 of 2 · the facts

Red Hat OpenShift is a certified Kubernetes distribution plus the services around it, sold by subscription with support and tested updates. It also runs virtual machines (OpenShift Virtualization). Release 4.22, on Kubernetes 1.35.

The market: parts of OpenShiftFrom: K8s = in every Kubernetes · OpenShift = added · Both = extended by OpenShift
1
API server
Front door of the cluster: checks every change and stores it in etcd.K8sConsole, oc and all controllers work only through it.
2
Scheduler
Assigns each new pod to a node with enough free CPU and memory.K8sWithout it, new pods stay Pending and never start.
3
Controller
A loop that compares desired and actual state and closes any gap.K8sThis loop heals the cluster: a lost pod is simply replaced.
4
Operator
A controller with expert know-how for one app: install, backup, upgrade.BothOpenShift’s own parts are operators: they roll out updates an admin starts.
5
Node
A machine (metal, VM or cloud) with RHEL CoreOS; its kubelet starts pods.BothUsually 3 nodes run the control plane; add workers to grow.
6
Pod
Smallest unit that runs: one or more containers sharing one IP, on one node.K8sDisposable: keep data on a persistent volume, not inside the pod.
7
Deployment
Declares how many copies of a pod to run and which image version.K8sRolls out new versions step by step, with rollback.
8
Service
A stable internal name and IP that spreads traffic over matching pods.K8sPods change their IPs; the service address stays the same.
9
Route
Publishes a service under an outside hostname via the built-in router.OpenShiftKubernetes uses Ingress or Gateway API; a plain Service stays internal.
10
Project
A namespace with its own access rights, optional quotas and network rules.BothLets many teams share one cluster; a project’s pods run on any node.
11
Container image
Read-only package of an app and all it needs (OCI format), in a registry.OCI standardSame image in test and production; OpenShift has a built-in registry.
12
Build and pipeline
Builds images in the cluster from source code (S2I) or a Dockerfile.OpenShiftOpenShift Pipelines (Tekton) chain build, test and deploy steps.
13
Access control (RBAC, SCC)
Login (OAuth) and roles (RBAC) for people; SCCs limit what pods may do.BothBy default no pod may run as root: root-only images fail here.
14
Web console and oc
Browser UI for admins and developers, with monitoring; oc extends kubectl.OpenShiftBoth talk only to the API server: what you click, you can script.
Other markets: alternatives and other ways to get OpenShift
15
Kubernetes
Open-source container orchestrator of the Cloud Native Computing Foundation (CNCF).CNCFFree, but ingress, registry, monitoring and updates are up to you.
16
OKD
Community distribution of OpenShift, on CentOS Stream CoreOS.CommunityGood for learning and labs; no Red Hat support.
17
Managed OpenShift
Run for you: ROSA (AWS), ARO (Azure), OpenShift Dedicated, IBM Cloud.Red Hat + cloudNo clusters to operate; Red Hat and the cloud provider run them.
18
Other platforms
Cloud Kubernetes (EKS, AKS, GKE), SUSE Rancher Prime, VMware VKS.Other vendorsCloud services bind you to one cloud; Rancher manages any Kubernetes.

  1. 1Layers, bottom up: machines or cloud → RHEL CoreOS → Kubernetes → OpenShift services → your apps.
  2. 2An image is the template, a container is one running copy, and a pod wraps one or more containers.
  3. 3You write down the desired state; controllers and operators keep reality matching it.
  4. 4Extras install as operators: OpenShift GitOps (Argo CD), OpenShift Pipelines (Tekton), Service Mesh (Istio).
  5. 5Routes, SCCs and S2I builds exist only on OpenShift; plain Kubernetes does not know them.
  6. 6Rule of thumb: it pays off for many apps or teams; one app on one server needs only Podman or Docker.
  7. 7Try it free: Developer Sandbox (browser) or OpenShift Local (laptop). OpenShift 5 is announced for 2026/27.
