The scene on page one, item by item
Browser
The program that shows web pages, e.g. Firefox, Chrome, Safari.Starts the lookup, asks for the page and builds it on screen.You would get raw text and code, nothing laid out.
URL
The web address, e.g. https://example.ch/shop/shelfSays how (https), to which server (domain) and for what (path).The browser would not know whom to ask, or for what.
Packets
Chunks of data, typically up to 1,500 bytes, each addressed.Carry every message, the lookup too, by routes that may differ.One big message would block the line; one error, resend all.
Routers
Devices at network junctions: your home router, then providers'.Read each packet's destination address, pass it one hop closer.Packets could not leave your home network.
DNS
Domain Name System: a helper server asks a root server, then .ch, then the site's own.Turns the name into an IP address; answers are cached for a set time.You would type numbers; if it fails: “server not found”.
IP address
A number for a device online, e.g. 192.0.2.10 or 2001:db8::10.Each packet carries both addresses, so replies find you.Nothing could be delivered: routers use numbers, not names.
TCP connection
Transmission Control Protocol; newer HTTP/3 uses QUIC instead.Handshake first; then confirms, resends and reorders the data.Pages would arrive with gaps or jumbled.
TLS certificate
A file tying a domain name to a public key, signed by a certificate authority.In the TLS handshake the server proves it holds the matching private key.The browser warns: the connection is not private.
Encryption
TLS: both sides compute a shared key no listener can work out, and scramble all data with it.Hides content and paths, detects tampering; addresses and usually site name stay visible.Anyone on the way, e.g. public Wi-Fi, can read and change your data.
HTTP request
A short message: method (GET, POST), path, headers such as cookies.Asks for one file; the browser sends one per file it needs.The server sends nothing: it only answers requests.
Web server
A computer running software such as nginx or Apache.Finds or generates the file and sends it back, to many at once.The browser reports that the site cannot be reached.
HTTP response
Status code (e.g. 200 OK, 404 Not Found), headers, the file.Tells whether it worked and what kind of file follows.No page to build, and no way to tell a page from an error.
HTML
HyperText Markup Language: text with tags for headings, links.Gives content and structure; names CSS, scripts, images to fetch.No page: everything else loads only because the HTML names it.
CSS
Cascading Style Sheets: rules such as h1 { color: navy }.Sets colours, fonts, spacing and layout, per screen size.Plain text and pictures stacked in the browser's default style.
JavaScript
A programming language run by the browser, walled off from your files.Reacts to clicks and typing, changes the page, fetches more data.Simple pages still work; maps, live updates and web apps do not.
Rendering
Steps: element tree (DOM) from HTML, CSS styles, layout, paint.Starts with the first HTML; fits it to your window and draws it.Nothing would appear on screen.

To remember

  1. The order. Name → number → connection → lock → request → response → build. On a return visit, saved answers and files let the browser skip steps.
  2. The padlock. It means the connection is encrypted and the certificate fits the site's name; some browsers now show a neutral icon instead. It does not mean the site is honest.
  3. One page, many orders. Every extra file is one more request; a typical page needs dozens, sent side by side over few connections.

Test yourself

  1. What can others on the way see when you use https?
    Which server you talk to (its address and usually its name), when and how much; not the pages or what you type.
  2. Why does a page look different on a phone?
    Rendering fits the same HTML and CSS to the window, and CSS can set other rules for small screens.
  3. Why can people still land on a site's old server for a while after it moves?
    DNS answers are kept (cached) for a set time before anyone asks again.
