The errand, as drawn in the scene (three zones mixed)
Browser The program that shows web pages, e.g. Firefox or Safari. Makes every request, then builds the page from the replies. No web page could be fetched or shown.
Web address (URL) Scheme, domain and path, e.g. https://example.org/shelf Says how (https: encrypted), which site (domain), which page (path). The browser would not know which site or page to fetch.
DNS resolver A lookup server, usually your internet provider’s or a public one. Asks the name servers for you and remembers answers (cache). Your device would have to query every name server itself.
Name servers DNS servers in levels: root, ending (.ch, .org), the domain’s own. Each points to the next; the domain’s own gives the IP address. No one could say which number belongs to a name.
IP address A computer’s number on the internet, e.g. 203.0.113.7. Stands on every packet, as destination and as sender. Packets would have nowhere to go.
Routers Devices joining networks, from your home router onward. Pass each packet one hop nearer, DNS lookups included. You could reach only devices in your own home.
TCP connection The usual delivery protocol; the newer HTTP/3 uses QUIC. Starts with three messages; numbers, confirms and resends packets. Lost or jumbled packets would garble the page.
TLS encryption Transport Layer Security: what secures HTTPS; replaced SSL. Agrees a key without ever sending it, then encrypts the data. Anyone on the route could read and change your data.
Certificate A domain’s digital ID, signed by a certificate authority (CA). Lets the browser check, via CAs it trusts, who the server is. Impostors could pose as the site; browsers warn.
HTTP request The browser’s message: method (GET), path, headers. Asks for one file and says what the browser accepts. The server would not know which page you want.
Web server Software on a computer, often in a data centre, e.g. nginx. Answers each request with a stored or freshly built page. Nothing answers: the site is offline.
HTTP response The server’s reply: status code, headers, content. Its code says how it went: 200 OK, 404 not found. No content, and no word on what went wrong.
Build the page: what the browser builds it from
HTML HyperText Markup Language: text marked up with tags. Sets structure and names further files: CSS, scripts, images. There is no page to build.
CSS Cascading Style Sheets: rules for how parts look. Sets colours, fonts, sizes and positions. Browser default styles: bare headings and links, one column.
JavaScript A language the browser runs, walled off from your files. Reacts to clicks and typing; changes the page after it shows. Pages still show, but menus and buttons may not work.
Rendering The browser turning HTML and CSS into pixels. Builds a tree of parts (DOM), lays them out, paints. You would see code, not a page.

To remember

The order. Look up, connect and lock, ask and receive, build. Cached answers and reused connections let later visits skip steps.

Name first, number second. Nothing reaches the site until its name has become an IP address (3–5).

One exchange. 8 and 9 happen in one TLS handshake; in TLS 1.3 the key comes first, then the certificate, already encrypted.

What HTTPS promises. 8 and 9 mean private and the right address, not that the site is honest.

What others still see. With HTTPS, onlookers see which site you visit, not which page or what you type.

One page, many deliveries. The HTML names further files, each requested the same way (10–12).

Which step failed? “Server not found”: usually the lookup (3–5). A security warning: the certificate (9). “404”: no such page (12).
