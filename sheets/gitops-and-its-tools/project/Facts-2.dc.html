Store · how the plan reaches the store: push or pull
Push deployment
pipeline runs kubectl apply or helm upgrade
 A deploy step at the end of a CI pipeline; the usual model before GitOps. Sends changes into the cluster from outside. Push, once per run; then nothing compares cluster and Git. GitOps: the pipeline holds cluster keys, and drift goes unseen.
Argo CD
part of the Argo project
 A GitOps controller with a web UI; each app is an Application object. Pulls from Git, compares, shows Synced or OutOfSync, applies. Applies on Sync, or by itself with auto-sync; self-heal also undoes hand-made changes. One instance can serve many clusters, holding their keys. Flux (14): Argo CD renders Helm charts to plain YAML, so no Helm release exists.
Flux
the GitOps Toolkit
 Small controllers: source, kustomize, helm, notification, image. Fetches sources, applies Kustomize and Helm, sends alerts. Reconciles on an interval and on webhooks; a web UI is an add-on. Argo CD (13): real Helm releases; usually one Flux per cluster.
Progressive delivery
Argo Rollouts, Flagger; works alongside 13 and 14
 A controller that rolls a new version out step by step. Canary shifts traffic in steps, blue-green at once; metrics decide: go on or roll back. During each rollout. Argo Rollouts replaces the Deployment; Flagger keeps it, adds a copy. Argo CD (13): Argo Rollouts is a separate Argo project.
Store · keeping the safe's code out of plain sight
Sealed Secrets / SOPS
 Two ways to keep secrets in Git, encrypted. Lets passwords sit beside the manifests, unreadable. Sealed Secrets: only its controller in the cluster decrypts. SOPS: age or cloud KMS keys; Flux (14) decrypts it natively. 17: the secret is in Git, so a change needs a commit.
External Secrets Operator
 A controller that copies secrets in from an external store. Keeps secret values out of Git; Git holds only a reference. Re-reads Vault or a cloud secret manager at an interval. 16: it needs a running secret store as the source of truth.
Building · the premises the store stands on
Terraform / OpenTofu
OpenTofu is the open-source fork
 Infrastructure-as-code CLIs; HCL files describe resources. Creates and changes networks, databases, whole clusters. Push, on command: plan against a state file, apply, then exit. Crossplane (19): drift shows only at the next plan.
Crossplane
 Controllers that manage cloud resources as Kubernetes objects. Creates and changes cloud resources described in YAML. Reconciles continuously, so Argo CD (13) or Flux (14) can deliver infrastructure too. Terraform (18): no state file; drift is corrected automatically.
