In the restaurant · scene items
Issue A tracked task, bug or idea, with labels and an assignee. One per piece of work; boards show issues as cards. “Closes #12” in a merge request closes it on merge into main.
Repository The project’s Git storage: all files and their full history. Browse it on the web or clone it to your computer. The default branch (usually main) is the shared truth.
Branch A separate line of commits in the repository. One per change: git switch -c fix-login main stays unchanged until the branch is merged.
Merge request A request to merge a branch, with diff, comments and approvals. Review, approve, merge once the pipeline is green. GitHub calls it a pull request. Required approvals: Premium.
Pipeline Jobs in stages (build, test, pack, deploy), set in .gitlab-ci.yml. Runs on each push; its result shows in the merge request. No file, no pipeline. A failed stage normally stops the rest.
Runner The agent that runs jobs, in a shell, Docker or Kubernetes. Use GitLab.com’s hosted runners or register your own. Hosted runners use compute minutes (Free: 400 a month).
Security scan Scanner jobs: code (SAST), secrets, containers, dependencies. Include GitLab’s scanner templates in the pipeline. Dependency scans, DAST and the vulnerability report: Ultimate.
Registry A per-project store for container images and packages. Pipeline jobs push to it; deploy jobs pull from it. Tag with a version or commit, not only latest.
Environment A named deploy target, such as staging, with its deployment log. Deploy jobs name it; GitLab shows what runs where. The servers are yours or a cloud’s; roll back by redeploying.
Web interface GitLab in the browser, from issues to settings. Plan, review and merge; the Web IDE edits files. Roles from Guest to Owner decide who may do what.
Git The open-source version-control tool on your computer. clone, commit, push, pull over HTTPS or SSH. Your clone has the full history; commits stay local until pushed.
API REST and GraphQL APIs, webhooks, and the glab CLI. Script tasks: glab mr create; webhooks alert other tools. Give tokens the smallest scope and an expiry date.
Doors and town · where the restaurant stands
GitLab.com GitLab’s shared cloud; Dedicated is a single-customer one. Sign up, create a group and a project, push. Nothing to install. Free: 5 users per private top-level group; 10 GiB storage.
Self-managed Your servers, cloud or Kubernetes; free open-source edition. Linux package, Docker or Helm; baseline 8 vCPU, 16 GB RAM. Patch fast: a critical flaw was exploited in Oct 2026.
Doors and town · three ways to set up the business
GitLab One app for plans, code, CI/CD, packages, security, deploys. One login, one permission model, one trail from issue to deploy. Premium $29 per user a month, billed yearly; Ultimate by quote.
GitHub Microsoft’s platform, with a very large developer community. Pull requests, Actions for CI/CD, Marketplace add-ons, Copilot. Self-hosting via paid Enterprise Server; security add-ons cost extra.
Separate tools Specialist tools joined up, such as Jira, Bitbucket and Jenkins. Each has its own interface; plugins and webhooks link them. Best tool per job, but more logins, licences and upkeep.

Questions to remember

Git or GitLab? Git keeps the history on every computer; GitLab is the shared place around it, with planning, review, pipelines and deploys.

Who does a pipeline’s work? Runners. GitLab plans the jobs and keeps the results.

When is GitLab the better pick? You want one tool for the whole flow, need free self-hosting, or need built-in security and compliance.

When the weaker one? Open-source reach matters most, you only need code hosting, or you must self-host but nobody can keep a server patched.

Rules to remember

The loop: issue → branch → push → merge request → pipeline → review → merge → deploy.

Protect main in the project settings: changes arrive only through a merge request with a green pipeline.

Where it sits: between your laptop (Git, editor) and your servers or cloud; runners and deploy targets are yours to choose.

First steps: free GitLab.com account → project → push → add .gitlab-ci.yml → open a merge request.
