Terraform

Learning sheet · page 2 of 2 · the facts, as of November 2026

Terraform is an infrastructure-as-code tool: you describe servers, networks and other services in text files, and Terraform creates, changes and deletes the real ones through each platform's API until they match the files.

The manager's office: the three steps you ask for, in order
init
terraform initInstalls providers, modules; sets up the backendRerun after such changes; commit its lock file
plan
terraform plan: a dry run that changes nothingLists + create, ~ update, −/+ replace, − destroyCheck every −/+ and −: data can be lost
apply
terraform apply: asks for yes, or runs a saved planCalls APIs in dependency order; updates stateWith no gap, a rerun changes nothing

Principles to remember

  1. Describe the end state, not the steps. Terraform derives the order from the references between blocks.
  2. The code is the truth. State is only Terraform's memory of what exists in the real world.
  3. Apply twice, change once. A second apply finds no gap and does nothing (idempotence).
  4. Any outside change to a managed object is drift; the next plan proposes to undo it.

Do

  • Keep the code in git and review every change.
  • Read the plan, then apply exactly that plan.
  • Keep state remote and locked, one per environment.
  • Run terraform fmt and validate before committing.
  • Adopt existing objects with an import block.
  • Pass credentials by environment or login, never in code.

Don't

  • Change managed objects by hand in a web console.
  • Edit, delete or commit the state file.
  • Put secrets in .tf or .tfvars files in git.
  • Skim past −/+ or − lines in a plan.
  • Put everything into one huge state.
  • Make -target or -auto-approve a habit.
